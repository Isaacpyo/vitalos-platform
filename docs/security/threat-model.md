# Threat model

Assets: editorial integrity, enquiries, credentials, controlled evidence and production availability. Primary threats: form abuse/injection, secret leakage, content-repository compromise, supply-chain compromise, broken authorization, DNS/deployment takeover and false public claims. Controls: boundary validation, rate-limit/Turnstile adapter, server-only persistence, least privilege/RLS, protected pull-request reviews of content, pinned lockfile, scanning, secure headers and reversible cutover. Residual risks remain until providers, owners and incident routes are configured.

## Browser-facing controls (workstream E, ADR-020)

| Threat                                             | Control                                                                                                                                                      | Residual risk                                                                                                                             |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Non-production build indexed by search engines     | `X-Robots-Tag: noindex, nofollow` on every response when `deployEnv` is not `production`; fails closed for unknown env values                                | A production-flagged deployment is indexable by design; the deploy env is set by the platform, not by request content                     |
| Cross-site scripting                               | Output escaping by React; CSP with `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, no third-party script origins except Turnstile when enabled | Scripts allow `'unsafe-inline'` (static rendering requires it; SRI spike did not remove it; re-evaluated in ADR-047). Injected inline script is not blocked by CSP; inline event-handler attributes are (`script-src-attr 'none'`) |
| Clickjacking                                       | `frame-ancestors 'none'` in every environment                                                                                                                | None known: `X-Frame-Options: DENY` is also sent for browsers without `frame-ancestors` (ADR-047)                                           |
| MIME sniffing, referrer leakage, powerful features | `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, restrictive `Permissions-Policy`                                      | None material                                                                                                                             |
| Downgrade / mixed content                          | `upgrade-insecure-requests` outside `local`; HSTS only after owner enables it (`ENABLE_HSTS`)                                                                | HSTS is off until the canonical host and DNS are validated; no `includeSubDomains` or preload                                             |
| CSP injection through configuration                | Frame-ancestor origins validated by a strict pattern; the build throws on anything else                                                                      | Misconfiguration fails the build rather than weakening the policy                                                                         |
| Client-side calls to external APIs                 | `connect-src 'self'` in every environment; `img-src 'self' data:` (no external image hosts, ADR-028)                                                         | None material                                                                                                                             |
| Personal data or secrets in logs                   | Structured logger redacts credential and enquiry personal-data keys and scrubs emails and bearer tokens in values; query strings stripped from logged paths  | Free text that is not an email (for example a name inside a message string) is not detected; callers must log identifiers, not content    |
| Log forging through a client-supplied request id   | `proxy.ts` accepts only `^[A-Za-z0-9._-]{8,128}$` ids, otherwise generates a UUID                                                                            | None material                                                                                                                             |
| Personal data in analytics                         | Closed event taxonomy with schema-validated, non-personal properties; invalid events dropped                                                                 | No provider yet; a provider adapter and consent approach need their own review                                                            |
| Unobserved server errors                           | `instrumentation.ts` `onRequestError` reports through the `ErrorReporter`                                                                                    | Console reporting only until the owner provides a Sentry DSN; no alert route                                                              |
| Vercel preview toolbar blocked by CSP              | Accepted: not allow-listed (ADR-020)                                                                                                                         | Cosmetic on preview deployments                                                                                                           |

## Enquiry email notification (ADR-019 status note)

| Threat                                                                                         | Control                                                                                                                                                                                                                                                             | Residual risk                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Enquiry personal data leaves to a third-party processor (Postmark or Resend) in the email body | The database stays the record; the email is a notification to one internal recipient. Subject carries reference and intent only; logs carry identifiers only; the customer acknowledgement email is refused; no provider is configured until the owner approves one | The body contains name, email, organisation and goal and is held by the provider and the recipient mailbox. Production use depends on owner approval of the provider, a data processing agreement, transfer assessment and a retention setting at the provider |
| API key compromise (`EMAIL_PROVIDER_API_KEY`)                                                  | Server-only; never in `NEXT_PUBLIC_*`; covered by the client bundle secret scan (names and `re_` values); never logged; set only in the provider secret store; errors carry codes, not bodies                                                                       | A leaked key can send mail as the sender domain. Owner to scope the key to sending only, rotate it on suspicion and monitor provider activity; there is no alerting yet                                                                                        |
| Sender spoofing or poor deliverability (`EMAIL_FROM` domain)                                   | `EMAIL_FROM` must be a single validated address; the provider only sends from verified senders                                                                                                                                                                      | Owner action: publish SPF, DKIM and DMARC for the sender domain before go-live. Until then notifications may be rejected or land in spam, and the domain can be spoofed                                                                                        |
| Header injection through enquirer-supplied values                                              | JSON API (no raw headers); reply-to set only when it matches a strict single-address pattern; subject uses a validated token                                                                                                                                        | None material                                                                                                                                                                                                                                                  |
