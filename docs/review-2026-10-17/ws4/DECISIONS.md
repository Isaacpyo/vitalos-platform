# WS4 decisions (Careers content and hygiene)

| #      | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Reason                                                                                                                                                      |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WS4-1  | The role page lives in `apps/web/src/templates/careers/RoleTemplate.tsx`. The brief calls it `JobPage.tsx`, and there is no `CareersIndex` or `map.ts`; the index is `CareersTemplate.tsx`. Changes went to the real files.                                                                                                                                                                                                                                     | The brief's names do not match the repo.                                                                                                                    |
| WS4-2  | The hiring process stays where the content API already puts it: `sections.process` on the role (its own text, else the careers default; `superadmin/apps/careers/public.py`). It is now rendered as its own panel (`ProcessBlock`) instead of a plain section, and only when there is text. No contract change.                                                                                                                                                 | Today's rule is "hidden while empty", so a new field or endpoint would be a second way of doing the same thing.                                             |
| WS4-3  | The "About Vitalos" strip builds the practices line from `@vitalos/cms` exports (`practiceNames` plus `navLabels.labs`, deduplicated) and uses the locked `propositionLong` and `ctas.secondary`. Nothing is hard-coded. If WS2 adds Labs to `practiceNames`, the line still says six. If WS2 adds a dedicated export, such as a six-practices sentence, the orchestrator can swap `practicesLine()` for it in one place (`features/content/careers/model.ts`). | Decision 1 (six practices including Labs). The brief says to reference the CMS export, not copy text, and WS2 is editing `locked-copy.ts` at the same time. |
| WS4-4  | The application form now uses the shared form primitives from `@vitalos/ui`: `Field`, `TextInput`, `Textarea`, `Checkbox`, `FormErrorSummary`, `Button`, `TextLink`, `Icon`. Before, it used its own input classes. The CV picker is styled to match: `rounded-sm` control surface, a secondary-button style "Choose a file", and a text-button "Remove".                                                                                                       | "Reuse the site's existing input styles". The contact form already uses these primitives, so the two forms now look and behave the same.                    |
| WS4-5  | Inline validation runs when you leave a field you have answered, and clears as soon as the answer is fixed. A required field left empty is reported only when you send. Errors are tied to fields with `aria-describedby` (the shared `Field` wiring) and `aria-invalid`. The right-to-work radios carry no `aria-invalid`, because the radio role does not support it (jsx-a11y): their group's `aria-describedby` points at the error instead.                | This avoids errors appearing just because you tabbed through, and still gives feedback straight away on a wrong email or URL.                               |
| WS4-6  | The confirmation adds "What happens next". Every line comes from approved copy: the live equal-opportunities statement ("We assess every application…") and the candidate privacy notice (use for assessing and contacting; withdrawal by email). The hiring process appears there when it is set. It promises no email.                                                                                                                                        | `CAREERS_CANDIDATE_EMAILS_ENABLED` is off, and the website has no way to know its value: the flag lives only in the admin and is not in the contract.       |
| WS4-7  | The confirmation's contact address comes from site settings (`loadChromeContent().settings.contactEmail`, checked with `safeEmail`) and is passed through the role route. The withdrawal line is left out when there is no address.                                                                                                                                                                                                                             | It stays one source for the address and keeps the content package out of the client bundle.                                                                 |
| WS4-8  | In `JobPosting`, a location of "United Kingdom" or "UK" on a hybrid or on-site role is sent as `addressCountry: "GB"`, not as `addressLocality`.                                                                                                                                                                                                                                                                                                                | The live Senior Technology Consultant page sent a country in the locality field.                                                                            |
| WS4-9  | The equal-opportunities statement was found **live**, not empty as FINDINGS B7 says. The draft quotes it and proposes no new claim.                                                                                                                                                                                                                                                                                                                             | The live site was checked by GET on 17 Oct.                                                                                                                 |
| WS4-10 | The draft-roles review is a follow-up with a read-only shell snippet.                                                                                                                                                                                                                                                                                                                                                                                           | The orchestrator confirmed no production export would come tonight.                                                                                         |
| WS4-11 | The worktree moved to `D:/Development/vitalos-ws4` after C: filled up, per the orchestrator's MOVE-TO-D note.                                                                                                                                                                                                                                                                                                                                                   | Installs failed with "not enough space on the disk".                                                                                                        |
