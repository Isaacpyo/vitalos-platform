# WS7 decisions — Super Admin bugs, identity, Overview, Architecture, Help

Each decision, with the reason. Architecture-level ones are also in [ADR-049](../../adr/ADR-049-superadmin-identity-and-morning-overview.md).

| #     | Area          | Decision                                                                                                                                                                                                                                                                                                                            | Reason                                                                                                                                                                                       |
| ----- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| W7-1  | Identity      | `full_name` is the one required display name. No `display_name` field was added. Required in forms; the column stays blank-able.                                                                                                                                                                                                    | Two fields meaning the same thing drift apart. Making the column `blank=False` is an AlterField that stops the automatic deploy guard; the form rule and the back-fill give the same result. |
| W7-2  | Identity      | Back-fill splits the email local part on `.`, `_`, `-` and `+` and capitalises each word; the user is flagged `name_needs_review` until they or a super admin save the name. New accounts created without a name (for example `create_owner`) get the same treatment.                                                               | The brief's example (`temitope.agbola` → "Temitope Agbola"); every person always has something better than an address to show.                                                               |
| W7-3  | Identity      | `link_people` matches team members by email (case-insensitive) and person authors by exact name, because `insights.Author` has no email field. It counts back-filled (unconfirmed) names, and says so in its report. It never overwrites or removes a link.                                                                         | The brief says "by email"; authors cannot be matched that way. An exact, unique name match is the safest rule that still links Temitope's author profile.                                    |
| W7-4  | Identity      | Audit-trail sentences show "Name (email)" for users; the CSV export keeps the stored email column unchanged. The actor filter matches name or email.                                                                                                                                                                                | Names for reading; a stable column for exports and anyone parsing them.                                                                                                                      |
| W7-5  | Overview      | The needs-attention list is back on the Overview, overdue first. This reverses an earlier choice (it had moved to Notifications only); the existing test was updated.                                                                                                                                                               | F1 asks for the morning screen to start with what needs attention.                                                                                                                           |
| W7-6  | Overview      | Relay numbers come from three existing client calls (`inbox("needs")`, `gaps(7)`, `knowledge(source="faq")`), with a 3-second timeout and a 60-second cache per user. "Last sync age" is the oldest of the CMS, repo and FAQ sync times, flagged over 24 hours.                                                                     | No counts endpoint exists yet (WS6 may add one); the Overview must not hang for 8 seconds when Relay is down. The oldest source is the one that matters for staleness.                       |
| W7-7  | Analytics     | Link-out card to `ANALYTICS_DASHBOARD_URL` plus an adapter interface (`apps/core/analytics.py`); no adapter registered. `ANALYTICS_PROVIDER` defaults to `vercel`.                                                                                                                                                                  | Vercel Web Analytics has no stable public read API; adding a provider with one is a single class.                                                                                            |
| W7-8  | Alerts        | New notification kinds (`enquiry_overdue`, `system_warning`) and outbox event (`sla_overdue`) are validated in code, not added to field `choices`.                                                                                                                                                                                  | A choices change is an AlterField, which stops the automatic deploy; `careers_application` already works this way (and Relay, DECISIONS 102).                                                |
| W7-9  | Alerts        | Overdue email follows the existing preferences: "Assigned to me" for the assignee; "New enquiry" for the unassigned case (owner instant, other super admins off by default). In-app goes to everyone in the audience.                                                                                                               | Respect preferences without adding a preference row type (another AlterField).                                                                                                               |
| W7-10 | Alerts        | Overdue email goes through the existing enquiry outbox (plain text like every other internal enquiry alert), so it is coalesced, rate-capped, counted towards `RESEND_DAILY_LIMIT` and rolled into the digest when the limit is near.                                                                                               | Using the shared HTML layout for one alert type would make enquiry alerts inconsistent; moving all of them to the layout is a follow-up.                                                     |
| W7-11 | Alerts        | The content tick now also flushes the enquiry outbox and sends the 08:00 digest. "Nightly digest of overdue items" = still-overdue enquiries are queued into the 08:00 digest by the tick's daily step.                                                                                                                             | `send_enquiry_notifications` may not be scheduled in production; the tick always runs. One digest, not a second email.                                                                       |
| W7-12 | Alerts        | The tick's HTTP response is unchanged; the new step counts go to `TickState.last_result`.                                                                                                                                                                                                                                           | `TickResponse` in the content-API contract is a strict object.                                                                                                                               |
| W7-13 | Smoke test    | `manage.py notifications_cleanup --purge-smoke-test` (dry run; `--apply` deletes) removes notifications titled "Smoke test …" and archived Practice/Solution/Offer/KPI/Project records named "Smoke test …". `e2e/smoke.py` now clears its own account's bell at the end.                                                           | The browser test cannot delete other users' notifications through the UI. Live records are never touched. Running it in production is an approval item.                                      |
| W7-14 | Health        | The sending-domain check runs daily from the tick and asks Resend `GET /domains` through `ResendOutbound.domain_status`. A sending-only API key gets a clear "sending-only API key" status rather than an error.                                                                                                                    | The provider adapter already owns Resend; the production key may be sending-only.                                                                                                            |
| W7-15 | Health        | The 80 % email warning counts enquiry, careers, candidate and Relay emails together (`core.email_usage.sent_today`). System health uses the same number.                                                                                                                                                                            | Each feature counted only part of the total before.                                                                                                                                          |
| W7-16 | Tables        | Row actions: a sticky right-hand actions column with one primary action (Edit; Review for applications) and a "More" menu (`<details data-row-menu>`, keyboard: Enter/Space to open, Esc to close). The menu panel is fixed-positioned by `app.js`, so the table's scroll wrapper never clips it. Archive confirms inside the menu. | One pattern for posts, roles and applications; works at 1440 and 390 without hiding actions off-screen.                                                                                      |
| W7-17 | Architecture  | `sync_architecture_from_web` reads a committed JSON export written by `tooling/content/export-architecture.ts` (run with the `tsx` already in `@vitalos/relay-knowledge`). No new dependency.                                                                                                                                       | Parsing TypeScript in Python is fragile; JSON is reviewable and needs no Node at run time.                                                                                                   |
| W7-18 | Architecture  | Website practice → the Practice of the same-slug service line; solution → its first listed practice; offer → its first listed solution. New records are Active, since they describe live pages. `public_url` built from `CONTENT_WEB_TARGETS[0]` (fallback `https://vitalos.co.uk`).                                                | The website taxonomy is a web; the admin's is a tree. The content's own ordering decides the lead parent.                                                                                    |
| W7-19 | Architecture  | `ARCHITECTURE_MODULE_ENABLED=false` hides the nav items and the activity service-line filter, and makes the Service lines, service dashboard and Architecture pages answer 404. The Team page drops its service-lines column. Data stays.                                                                                           | "Hide" as one toggle that is easy to undo.                                                                                                                                                   |
| W7-20 | Help          | Six guides live in `apps/core/guides.py`, rendered on `/help/`, written from the templates (button labels quoted exactly).                                                                                                                                                                                                          | Keeps copy reviewable in one place.                                                                                                                                                          |
| W7-21 | F7            | `transfer_primary_owner --to <email> [--apply]` refuses unknown, inactive or no-2FA targets and never creates accounts. Nothing was run.                                                                                                                                                                                            | Primary-owner changes are approval items.                                                                                                                                                    |
| W7-22 | CSP (for WS3) | The Super Admin's `img-src` adds the origin of `CONTENT_MEDIA_PUBLIC_BASE_URL` (scheme and host only; https or http, no credentials) when it is set, so Insights cover previews and a future media library load from the media host. Nothing else is widened.                                                                       | The media host is another origin in production; settings are WS7's.                                                                                                                          |
