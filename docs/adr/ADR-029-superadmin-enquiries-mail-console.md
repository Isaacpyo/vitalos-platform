# ADR 029 Super Admin enquiries, mail and console design

Status: Proposed (12 Oct 2026). Owner approval is needed before any mail provider, Worker or DNS change goes live (`superadmin/docs/email-setup.md`).

Context: the Super Admin (ADR-026) is live at https://admin.vitalos.co.uk. The upgrade adds an Enquiries tab for mail sent to support@vitalos.co.uk and the website contact form, outbound mail (replies, sign-in and set-password links, notifications), a primary-owner model, an append-only audit trail and a restyled console. Facts recorded 11 Oct 2026: DNS is on Cloudflare; inbound mail uses Cloudflare Email Routing (support@ appears to forward to a shared Gmail inbox, to be confirmed); SPF is `v=spf1 include:_spf.mx.cloudflare.net include:_spf.google.com ~all`; DMARC is `v=DMARC1; p=none;`; no DKIM was found; Google Workspace was cancelled in Feb 2026 so the Google SPF include is probably stale; Microsoft 365 is planned but not live in DNS; a Resend account exists with domain verification unknown. Sanity was dropped on 11 Oct 2026, so editorial content is repository files and the website's operational records stay in PostgreSQL; the Super Admin keeps its own database (ADR-026).

Decision:

1. **Mail behind a provider interface.** The app depends on a `MailProvider` interface (apps/mailer, apps/enquiries) with these adapters:
   - **Inbound, primary: a Cloudflare Email Worker** (`infra/cloudflare-email-worker`). It forwards each support@ message to the existing inbox first, then posts the raw MIME, signed with HMAC-SHA256 over `timestamp.` plus the body, to `POST /api/inbound/email`. The app rejects timestamps more than 5 minutes off (401) and bodies over 25 MiB (413), and de-duplicates by Message-ID. The Worker never throws after a successful forward, so a failure of the app cannot bounce a sender or lose mail from the existing inbox.
   - **Inbound, fallback: Resend Inbound** on a subdomain such as `inbound.vitalos.co.uk`, with a Cloudflare Email Routing rule forwarding support@ there, selected with `INBOUND_PROVIDER=resend`.
   - **Inbound, later: Microsoft Graph**, when Microsoft 365 is live (`INBOUND_PROVIDER=graph`).
   - **Outbound: Resend**, with delivery events on `POST /api/webhooks/resend` (Svix-signed). `EMAIL_TRANSPORT` defaults to `log`, which sends nothing, so deploying the code sends no mail until a person sets `resend`.
2. **The website form posts to `POST /api/inbound/web-form`** with the same signature scheme over the JSON body, a honeypot field and an optional Turnstile token. Changing `apps/web` is a separate, signed-off change; the runbook holds the sketch. Applications still cannot import each other's source: the only coupling is this HTTP contract.
3. **Operational records stay in PostgreSQL.** Enquiries, messages and the audit trail live in the Super Admin's database. Message HTML is rendered only in a sandboxed iframe with its own Content-Security-Policy, with remote images loaded only on request. Attachments are not stored unless private S3-compatible object storage is configured (`django-storages[s3]`, for example a private Cloudflare R2 bucket); without it only names and sizes are kept. Controlled evidence does not belong here.
4. **Access.** Enquiries are visible to SuperAdmin and ServiceLead only. There is one primary owner (`PRIMARY_OWNER_EMAIL`, `admin@vitalos.co.uk`): only the owner grants or revokes SuperAdmin; the owner cannot be demoted or deactivated; existing SuperAdmins are kept. The owner has no initial password: `manage.py issue_setup_link` prints a single-use 30-minute link to the terminal only. Forgot-password is offered only when mail can be delivered, and the sign-in page does not pre-fill an email by default. TOTP stays mandatory for SuperAdmin. Entra OIDC remains Phase 2 item 1; passkeys are deferred.
5. **Environment names.** The app keeps `APP_ENVIRONMENT`; `APP_ENV` and a `SUPER_ADMIN_EMAILS` list are not introduced.
6. **Console design, scoped to the Super Admin.** Palette: Midnight `#0B1320`; Cobalt `#2F6BFF`, `#2458E6`, `#7FA3FF`; Mineral `#18B7A0`, `#0E7C6B`, `#3FD0BA`. Type: Manrope (headings), Inter (body) and JetBrains Mono (code), self-hosted. The palette is not applied to the website: `packages/design-tokens` still holds `#2457FF` and `#081A2A` pending the owner decision in `docs/brand/token-reconciliation.md`, and this ADR does not settle it. If the owner later picks the console blues for the website, that is a separate token change.
7. **New dependencies** `nh3` (HTML sanitising) and `django-storages[s3]` (attachment storage), with the lockfiles compiled with `--python-platform linux`.

Options considered: parsing mail in the Worker (rejected: Workers Free CPU limits, and logic would sit outside the tested app); Resend Inbound as the primary (kept as the fallback: it needs an inbound subdomain and changes where support@ mail goes); Microsoft Graph first (not live); a Postgres-backed queue or a hosted mail service for notifications (rejected: a Container Apps scheduled job inside the free grant is enough); sharing the website's database (rejected, ADR-026).

Reasons: the Worker keeps the existing inbox as the system of record for mail while the app is proven, adds no new inbound MX and costs nothing on the free tiers; signed requests and Message-ID de-duplication make retries safe; the provider interface keeps Resend, Cloudflare and Microsoft out of business rules.

Trade-offs: mail passes through a Worker the owner must deploy and monitor; Cloudflare does not promise that `forward()` still works after the raw stream is read, so a post-deploy test is required (runbook, test plan); Resend's free tier (3,000 a month, 100 a day, to be rechecked) caps outbound volume, which `RESEND_DAILY_LIMIT` respects; a 5-minute notification job uses part of the Container Apps free grant; DMARC stays at `p=none` until DKIM passes for every sender.

Consequences: new management commands `create_owner`, `issue_setup_link`, `send_enquiry_notifications` and `enforce_enquiry_retention` (a dry run unless `RETENTION_ENFORCE=true`; retention is 24 months, approved 11 Oct 2026). New secrets live only in Container Apps and the GitHub `Production` environment (`superadmin/docs/DEPLOY.md`). The architecture documentation for the Super Admin is updated in `superadmin/README.md` and `superadmin/docs/DECISIONS.md` (#63 onward).

Revisit triggers: Microsoft 365 going live (add the Graph adapters); Entra SSO (Phase 2 item 1); Resend limits or terms changing; the owner settling the website palette; moving DMARC to `quarantine`; mail volume exceeding the free tiers.
