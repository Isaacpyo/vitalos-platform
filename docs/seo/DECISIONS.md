# SEO decisions log

Decisions taken while designing and building SEO for vitalos.co.uk (`feat/seo`, from 16 Oct 2026), where the brief was unclear or met the repo as it is. Newest last.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                           | Why                                                                                                                                                                                                        |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Branched `feat/seo` from `main`.                                                                                                                                                                                                                                                                                                                                                                                                   | The page redesign (#41) is merged.                                                                                                                                                                         |
| 2   | **The live site is this app, and its canonical host is www today.** Code reads the host from `NEXT_PUBLIC_SITE_URL` as before. The brief's target, apex `https://vitalos.co.uk`, is the default in docs and tests. The host move (Vercel primary domain, the env var, a www → apex 308, Search Console) is prepared in LAUNCH.md, not executed.                                                                                    | The brief assumed a pre-launch site served by another project. In fact `www.vitalos.co.uk` serves `main` and is crawlable (AUDIT.md). Domain settings are on the stop list.                                |
| 3   | The shared SEO module stays at `apps/web/src/features/seo/`, not a new `src/lib/seo/`.                                                                                                                                                                                                                                                                                                                                             | It already holds `buildMetadata`, JSON-LD, robots and sitemap, and every route already uses it. "Never add a second way of doing the same thing."                                                          |
| 4   | The IA is used as it is: **5 practices** (Labs is separate), **6 solutions**, **13 offers** and **4 industries**.                                                                                                                                                                                                                                                                                                                  | The brief says 6/5/12/4, but the locked content (`packages/cms/src/draft/slugs.ts`) and design decision 3 say otherwise.                                                                                   |
| 5   | The crawler parses HTML with `parse5`, not jsdom or Playwright.                                                                                                                                                                                                                                                                                                                                                                    | It is already in the lockfile, has no peer dependencies (jsdom's optional peer broke the root install under pnpm 12), and server HTML is exactly what is being audited.                                    |
| 6   | Lighthouse 13.5.0 runs directly from `tooling/seo/lighthouse.mjs` with budgets in `tooling/seo/budgets.json`, not through `@lhci/cli`.                                                                                                                                                                                                                                                                                             | `@lhci/cli` has not been released since June 2025 and pins Lighthouse 12 with old Express and Inquirer, which risks the `pnpm audit` gate. A 100-line runner with Playwright's Chromium does the same job. |
| 7   | Lighthouse skips its `is-crawlable` audit when it runs off the canonical host. Crawlability is asserted by the production-mode crawl in `seo:check`, which sends `Host:` the canonical host.                                                                                                                                                                                                                                       | A local server is a non-canonical host and is correctly `noindex` (decision 9), so the audit would always fail there.                                                                                      |
| 8   | FAQ rich results ended on 7 May 2026 (Google Search Central, checked 16 Oct 2026). FAQPage markup goes only on pages whose visible Q&A they own (the solution pages), not on `/faq`, which repeats the same questions.                                                                                                                                                                                                             | The brief keeps FAQPage for understanding. Google's long-standing rule is to mark up repeated FAQ content once.                                                                                            |
| 9   | **Only the canonical host is indexable.** robots.txt and `X-Robots-Tag` depend on the deploy env **and** the request host. A production deployment answering on `*.vercel.app` (or any other host) is `noindex` and `Disallow: /`.                                                                                                                                                                                                 | AUDIT finding 1: `vitalos-platform.vercel.app` serves production and is indexable.                                                                                                                         |
| 10  | Crawler policy, checked against vendor docs on 16 Oct 2026: OpenAI (GPTBot, OAI-SearchBot, ChatGPT-User), Anthropic (ClaudeBot, Claude-SearchBot, Claude-User), Perplexity (PerplexityBot, Perplexity-User), Google-Extended, Applebot-Extended, CCBot and meta-externalagent. ChatGPT-User and Perplexity-User say robots.txt may not apply to user-initiated fetches, so their rules are a statement of intent, not a guarantee. | The brief asks for rules checked against current docs.                                                                                                                                                     |
| 11  | PR #46 (Insights and Careers, open) edits the same SEO files. This branch leaves `articleJsonLd`, `jobPostingJsonLd` and the Insights and Careers pages alone, adds new code in new files, and splits the sitemap so #46's `mergeContentSitemap` feeds the insights and careers children.                                                                                                                                          | It keeps the two PRs' conflicts small and mechanical.                                                                                                                                                      |
