# 05 — Discovery questionnaire and workflow observation guide

Status: draft v0.1, 28 Oct 2026 · Supports: VAD-011 · FDE-01 Discover, FDE-02 Diagnose

_Use this to run a discovery conversation (30–45 minutes) and, where the customer agrees, to observe one real run of the workflow. Output: notes in the grid below → [04-customer-problem-brief.md](04-customer-problem-brief.md) → scores in [02-qualification-scorecard.md](02-qualification-scorecard.md)._

## Before the call

- [ ] Enquiry read in the Super Admin; first-pass score and ICP screen done ([01](01-ideal-customer-profile.md)).
- [ ] Purpose agreed with the contact: understand one workflow; no obligation; no data to be sent yet.
- [ ] Note-taking consent: ask before recording. If recording, say where it is stored and when it is deleted. _Default: take written notes, do not record._
- [ ] Ask the contact to invite the decision-maker and the person who does the work.
- [ ] Remind yourself: **do not ask for or accept customer data during discovery.** Samples come later through an approved route ([09](09-onboarding-and-data-access-checklist.md)).

## 1. Questions (blueprint §8.2, grouped)

_You do not need every question. Get the bold ones answered; follow the conversation for the rest._

### The process

1. **What exact process are you trying to improve?** Where does it start and finish?
2. What triggers it (a document arriving, month-end, a client request)?
3. What parts are predictable or rules-based? Which need judgement?

### People and volume

4. **Who performs it?** How many people, which roles?
5. **How often does it happen?** Per day/week/month; peaks?
6. **How long does it currently take?** Per item and in total. Is that measured or a feeling?

### Systems and data

7. **Which documents, databases and software are used?** How do documents arrive (email, portal, post)?
8. Can the relevant data be exported? In what format?
9. **What data could you authorise Vitalos to use?** Who owns it? Are there client terms or confidentiality obligations that govern sharing it?
10. Does it contain personal data (for example sole-trader suppliers, employee names, customer contact details)?

### Exceptions, errors and control

11. **Where do exceptions and errors happen?** Give the last two examples.
12. **What is the impact of those errors?** (Rework, late payments, client complaints, financial loss.)
13. **Which decisions require human approval?** Who signs off today?
14. What must never happen automatically (posting, paying, emailing clients)?

### Alternatives

15. **What alternative software have you already tried?** What did it solve, what did it leave?
16. If nothing changed, what would you do instead (hire, overtime, accept it)?

### Commercial

17. **Who is the buyer and who must approve the change?**
18. **How much improvement would justify the investment?** What would make this worth paying for?
19. Is there a budget or a time by which this must be fixed?
20. How do you usually buy services like this (quote, purchase order, card)?

### Success

21. **How will we measure success?** What number would you check?
22. What would make you stop a pilot?

### Close

23. Could we watch one real run of the workflow (screen share or on site), with any confidential details hidden?
24. Next step and date. _Do not quote a price you have not checked against the cost tracker; say the fee will be confirmed in writing._

## 5. Observing one real run of the workflow

_Where practical, watch one complete execution rather than relying on a verbal summary. It is the fastest way to a credible baseline._

**Set-up**

- [ ] Customer agrees; they choose a representative (not the easiest) item.
- [ ] They share their screen or you sit beside them; **you do not take copies** of documents or screens. Confidential details can be hidden.
- [ ] No recording unless explicitly agreed.

**While watching, note**

| Step | What the person does | System / document | Start–end time | Judgement or rule? | Exception or rework? |
| ---: | -------------------- | ----------------- | -------------- | ------------------ | -------------------- |
|    1 |                      |                   |                |                    |                      |
|    2 |                      |                   |                |                    |                      |
|    3 |                      |                   |                |                    |                      |

- Hand-offs between people or systems.
- Copy-paste or re-keying.
- Look-ups (searching a ledger, opening an email).
- Where they hesitate or check something twice — that is where errors live.
- What "done" looks like and who checks it.

**Afterwards**

- [ ] Total observed time vs their estimate (record both).
- [ ] Is this item typical? How often are items harder?
- [ ] Thank them; confirm nothing was copied or retained.
- [ ] Update the problem brief and re-score.
